# Установка своего прокси-сервера

[На главную](README.md)

Используем [MegaProxyServer](https://github.com/andre487/MegaProxyServer): мастер сам устанавливает нужные программы и создаёт настройки для клиентов. Эта инструкция рассчитана на новый сервер без сайтов и других важных данных.

Если уже есть сервер с работающими сервисами, сначала попросите [агента](agent-guide.md) проверить его: установка меняет настройки SSH, сети и служб.

## 1. Подготовьте сервер и домен

1. У своего хостинг-провайдера арендуйте небольшой виртуальный сервер — **VPS** — с Ubuntu 24.04. Для начала выберите минимальный тариф, который соответствует [требованиям MegaProxyServer](https://github.com/andre487/MegaProxyServer/blob/main/docs/ru/README.md). Учитывайте страну сервера, оплату и включённый объём трафика.
2. Сохраните публичный IP сервера, логин, SSH-порт и способ входа из панели хостинга. SSH — подключение для управления сервером.
3. Зарегистрируйте домен или используйте поддомен своего домена, например `proxy.example.net`.
4. В панели управления доменом добавьте DNS-запись: тип **A**, имя вашего поддомена, значение — публичный IPv4 сервера. Если панель включает проксирование DNS-записи, выключите его: адрес должен вести прямо на VPS.
5. Дождитесь, пока домен начнёт указывать на IP сервера. Не добавляйте запись **AAAA**, если не настраивали IPv6.
6. Если у хостинга есть сетевой экран, разрешите входящие TCP-подключения на текущий SSH-порт, порт **80** и порт **443**. Порт 80 нужен для выдачи и обновления сертификата, 443 — для HTTPS-прокси. Текущий SSH-порт не закрывайте.

Домен нужен для простого подключения с доверенным сертификатом — подтверждением подлинности сервера. В этом руководстве используем автоматический сертификат Let's Encrypt (ACME).

## 2. Подключитесь к серверу

На Windows откройте PowerShell, на macOS или Linux — Терминал. Команды в этом разделе выполняются **на вашем компьютере**.

Если хостинг дал пользователя `root` и обычный SSH-порт:

```sh
ssh -t root@SERVER_IP
```

Замените `SERVER_IP` на IP из панели хостинга. Если логин или порт другие, используйте:

```sh
ssh -t -p SSH_PORT LOGIN@SERVER_IP
```

Здесь замените `SSH_PORT`, `LOGIN` и `SERVER_IP` своими значениями. Если хостинг выдал ключ, используйте его по инструкции хостинга.

При первом входе сверьте отпечаток SSH-ключа с данными хостинга, затем подтвердите подключение. Введите пароль, если требуется: при вводе символы не отображаются, это нормально.

После входа команды выполняются **на сервере**. Оставьте это окно открытым до конца установки.

## 3. Запустите мастер

На сервере установите программу загрузки:

```sh
sudo apt-get update
sudo apt-get install -y curl ca-certificates
```

Затем запустите официальный установщик:

```sh
curl -fsSL https://raw.githubusercontent.com/andre487/MegaProxyServer/main/install.sh | sudo bash
```

Если вошли как `root` и команда сообщает, что `sudo` не найдено, выполните эти команды без `sudo`, а в последней замените `sudo bash` на `bash`.

Мастер задаст вопросы. Для первого сервера:

- Задайте понятное имя сервера и укажите его публичный адрес.
- Укажите текущий административный логин и SSH-порт. Выберите или создайте административный ключ.
- Включите **HTTPS**. Дополнительные протоколы и цепочки серверов пока не нужны.
- Для сертификата выберите **ACME / Let's Encrypt для домена** и укажите домен из первого шага. Самоподписанный сертификат для этой инструкции не выбирайте.
- Создайте пользователя прокси и сохраните его логин и случайный длинный пароль в менеджере паролей.
- Если включаете маскирование (**probe resistance**), укажите **knock host** — имя доступного HTTPS-сайта. Это сайт для начала авторизации, не адрес вашего прокси. Один и тот же адрес должен быть разрешён на сервере и записан в клиентском профиле; мастер добавит его в готовый файл.
- Задайте и сохраните пароль **Ansible Vault**: это пароль защиты настроек сервера, он понадобится для дальнейшего управления.

**До подтверждения применения сохраните административный приватный ключ на компьютер.** Мастер покажет путь. Установка отключает вход администратора по паролю и вход `root`, поэтому без ключа можно потерять доступ.

Если первоначально вошли как `root`, откройте **второе окно терминала на компьютере** и выполните:

```sh
scp -P SSH_PORT root@SERVER_IP:KEY_PATH ./megaproxy-admin
```

Замените `SSH_PORT`, `SERVER_IP` и `KEY_PATH` значениями из панели и мастера. На macOS и Linux ограничьте доступ к скачанному ключу:

```sh
chmod 600 ./megaproxy-admin
```

На Windows храните ключ в личной папке, без общего доступа. Если первоначальный логин другой и файл читается только через `sudo`, используйте [способ передачи с sudo](https://github.com/andre487/MegaProxyServer/blob/main/docs/ru/README.md#установка-на-самом-сервере) с помощью агента; не открывайте файл для всех пользователей.

## 4. Завершите установку и проверьте вход

1. После сохранения ключа подтвердите применение в мастере.
2. Дождитесь успешного завершения установки и проверки сервера.
3. Не закрывая первое окно, во втором окне **на компьютере** проверьте новый вход:

```sh
ssh -t -i ./megaproxy-admin -p SSH_PORT ADMIN_LOGIN@SERVER_IP
```

Подставьте административный логин, порт и IP из мастера. Логин администратора и логин пользователя прокси — разные вещи.

Только после успешного нового входа можно закрывать первоначальное подключение. Если новый вход не работает, сохраните исходную сессию и попросите агента помочь.

## 5. Заберите файл настроек

В папке, где на компьютере лежит ключ, выполните команду ниже. Она сохранит клиентский файл на компьютер, не выводя его содержимое на экран:

```sh
ssh -i ./megaproxy-admin -p SSH_PORT ADMIN_LOGIN@SERVER_IP "sudo -n cat /opt/megaproxy-server/.generated/configs/MegaProxy.json" > MegaProxy.json
```

Замените значения подключения своими. Проверьте, что команда завершилась без ошибки и файл не пустой. Если копирование не получилось, не импортируйте полученный файл — попросите помощи у агента.

`MegaProxy.json` содержит пароли. Храните его, административный ключ и пароль Vault приватно; не отправляйте их в открытые чаты и не публикуйте на GitHub. Если создавали нескольких пользователей, общий экспорт может содержать данные всех: другим людям передавайте только их настройки.

Теперь выберите устройство:

- [Настроить BrowserMegaProxy на компьютере](desktop.md).
- [Настроить AndroidMegaProxy на телефоне](android.md).

Установка завершена, когда проверка в клиенте проходит, внешний IP соответствует серверу и нужный сайт или приложение работает. Успешная установка сервера сама по себе ещё не проверяет доступ из вашей сети.

## Если возникла ошибка

- **Не удаётся войти по SSH:** проверьте IP, логин, порт и сетевой экран хостинга.
- **Не выдаётся сертификат:** проверьте DNS-запись домена и доступность порта 80. Домен должен вести прямо на ваш сервер.
- **Мастер остановился:** сохраните текст ошибки без секретов. Не переустанавливайте сервер; мастер можно запустить повторно.

Для повторного запуска мастера выполните **на сервере**:

```sh
sudo /opt/megaproxy-server/mega-proxy setup-local
```

Дальнейшее управление и резервные копии описаны в [русском руководстве MegaProxyServer](https://github.com/andre487/MegaProxyServer/blob/main/docs/ru/README.md). Периодически устанавливайте обновления системы и проектов; сохраняйте приватные резервные копии ключей и настроек.
